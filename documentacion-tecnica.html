1. Visión general

PIE MASTER permite a los equipos PIE (Programa de Integración Escolar) crear, gestionar e imprimir la documentación oficial: PACI, PAI, FUDEI, FUR, informes psicopedagógicos, registros de atención y más — 13 tipos de documento del ciclo PIE chileno.

  • Marca / producto: PIE MASTER. Proyecto Cloudflare: proyecto-paci (nombre histórico).
  • Producción: proyecto-paci.pages.dev · Repo: github.com/CarlosFullStackAI/paci-master
  • Costo: $0 — todo corre en tiers gratuitos (regla del proyecto: solo servicios gratis).
  • Tenant inicial: Escuela Luis Cruz Martínez (Pulebu, Biobío), slug lcm-pulebu.

2. Arquitectura

Navegador (HTML + JS vanilla + Tailwind 3)
   │
   ▼
Cloudflare Pages  ──  sitio estático + Pages Functions (serverless, ESM)
   │                        │
   │   functions/_middleware.js  → bloquea archivos internos (404)
   │                        │
   ├── D1 "paci-db" (SQLite)      → estudiantes, documentos, OAs, tenants, auditoría

4. API (backend — Cloudflare Pages Functions)

Convención de cada endpoint (en este orden)

  1. Autenticación: getUser(request, env) de auth-helper.js → 401 si no hay sesión.
  2. Permisos: checkPermission(user.role, 'accion') de rbac-helper.js.
  3. Aislamiento por colegio: resolveTenant(request, env, user) de tenant-helper.js; toda query filtra por tenant_id.
  4. Cifrado: campos sensibles (RUT, diagnóstico, apoderado, observaciones) con crypto-helper.js (AES-256-GCM) antes de guardar.
  5. SQL: solo prepared statements (.prepare().bind()).

6. Multi-establecimiento (multi-tenant)

  • Resolución del colegio: subdominio del Host (lcm-pulebu.dominio.cl) → si no hay, el tenantSlug del perfil del usuario → si el usuario no tiene y existe UN solo colegio activo, ese (fallback mono-colegio). Un subdominio nunca otorga acceso cross-tenant.
  • Registro cerrado: cada colegio tiene un join_code; sin él no hay registro (el admin lo ve/regenera en admin.html).
  • Datos compartidos por colegio: todos los docentes del mismo tenant ven los mismos estudiantes/documentos (equipo PIE colaborativo).
  • Calendario escolar por colegio (migración 015): trimestres, vacaciones, días sin clases y eventos viven en tenants.calendario_json, editables en admin.html. Las constantes en app.html/dashboard.html son solo fallback si la red falla; aplicarCalendarioTenant() las muta en runtime.
  • Subdominios reales: requieren dominio propio + DNS wildcard en Cloudflare (pendiente de Carlos; pages.dev no sirve subdominios arbitrarios).
  • data/tenants/<slug>/config.json es documentación/respaldo del tenant — NO se carga en runtime (todo sale de D1).

7. Seguridad

  • Contraseñas: PBKDF2 (100.000 iteraciones, SHA-256) + salt UUID. Irrecuperables; reset, no recuperación.
  • Cifrado en reposo: AES-256-GCM para RUT, diagnóstico, apoderado y observaciones (llave en secret ENCRYPTION_KEY, nunca en código ni BD).
  • Sesiones: cookie HttpOnly + SameSite=Strict, token doble-UUID, TTL 24h. Rol y colegio se leen frescos del perfil en cada request.
  • RBAC: roles admin, coordinator, teacher, educador_diferencial, profesor_asignatura, utp; permisos centralizados en rbac-helper.js (Map, no objeto: anti prototype-pollution). Cuenta maestra: MASTER_ADMIN_EMAIL.
  • Rate limiting: registro 5/IP/15min; login también limitado.
  • Auditoría: audit_logs con datos enmascarados (maskRut/maskName).
  • Bloqueo de archivos internos: functions/_middleware.js responde 404 para /functions/*, /migrations/*, /specs/*, /scripts/*, /archive/*, CLAUDE.md, wrangler.jsonc, package.json, esta página, etc. (antes el código fuente era público — corregido 2026-06-12).
  • Checks pre-deploy: npm run security:all = npm audit + ESLint con plugin de seguridad (corre dentro de npm run deploy).

8. Inteligencia artificial

  • Proveedor: OpenRouter, SOLO modelos :free (regla: costo cero), con cadena de fallback entre 2-3 modelos. Fetch nativo, sin SDKs.
  • Usos: chatbot asistente, redacción de documentos (fill-document), autocompletar ficha del estudiante, adaptar OAs, generar clases/metas/secuencias por trimestre.
  • Protecciones: endpoints con auth (no queman cuota terceros), input del usuario envuelto en <pregunta_usuario> contra prompt-injection, max_tokens siempre presente.
  • Contexto por colegio: recursos, contexto de aula, intereses y DUA se guardan en D1 (ai_contexts) y los comparte todo el equipo del colegio.

9. Documentos PIE (los 13 tipos)

Registro central en docs-registry.js: 3 fases (Ingreso, Planificación y Gestión, Seguimiento y Reevaluación), cada tipo con schema de secciones/campos, referencia normativa, URL del formato oficial MINEDUC y reglas de recurrencia (DOC_RECURRENCE: once / annual / trimester / semester / periodic-fur / continuous + obligatoriedad).

  • PAI (D170): obligatorio para TODO estudiante PIE → required: true. PACI (D83): solo si requiere adecuar OAs → required: false. Tener PACI no exime del PAI.
  • Informe Psicopedagógico (Cartilla 4 MINEDUC 2025, obligatorio desde ingresos 2026): son DOS instrumentos en uno — el informe (firma el profesional PIE) + la Pauta de Evaluación y Observación Pedagógica (firma el docente de aula regular; escala En inicio/En desarrollo/Logrado/No observado, 20 indicadores). Verificado contra el .docx oficial.
  • FUDEI: la carga real es online en fudei.mineduc.cl; la app genera borrador + registra folio. FUR: formatos oficiales por diagnóstico (TEL, DEA, TDA, FIL, DI, TEA) con recordatorios automáticos (cron).
  • PDF: server-side vía Browser Rendering (/api/generate-pdf), con fallback a window.print().
